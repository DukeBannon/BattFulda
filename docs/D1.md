# D1 cc65 engine foundation

D1 proves the project architecture before combat rules are added: external data
compilation, a C64 map renderer, units, a bounded cursor, and simultaneous mouse
and joystick input using cc65's supplied drivers.

## Production toolchain

- `src/main.c`: game initialization, rendering, frame loop, and logical input.
- `src/assets.s`: ca65 wrapper that links generated binary assets.
- `tools/compile_data.py`: validates editable JSON and writes compact binaries.
- `build.ps1`: authoritative clean, test, compile, link, and VICE launch command.

Kick Assembler and the experimental hand-written input driver are no longer
part of the production build. Assembly remains available for future routines
that profiling shows need it.

## Compiled data

- `map.bin`: width, height, then one tile ID per cell.
- `scenario.bin`: format version, initial cursor X/Y, and unit count.
- `units.bin`: record count followed by five-byte side/type/X/Y/strength records.

Generated files are build products and are not checked into Git.

## Input contract

The cc65 `c64-1351` driver reads a standard 1351 on Control Port 1. The
`c64-stdjoy` driver reads a standard joystick on Control Port 2. VICE maps its
numeric keypad joystick to Port 2. Direct WASD keyboard input provides a third,
emulator-independent control path. All inputs update the same map cursor and
either fire button updates the visible input status.

Using separate control ports avoids analog-port switching and allows mouse and
joystick control to coexist on a standard C64.

VICE starts with host mouse capture disabled so the cursor cannot move merely
because the pointer crosses the emulator window. Press Alt+M to enable or release
1351 capture deliberately.

## D1 completion criteria

- A clean PowerShell build compiles the data and C64 executable.
- Automated data-format tests pass.
- VICE reaches the tactical map without an input-driver error.
- Mouse movement, keypad joystick movement, and both fire inputs are confirmed
  interactively.
