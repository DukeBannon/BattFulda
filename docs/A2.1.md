# A2.1: Relational data foundation

A2.1 establishes SQLite as the authoritative development store for relational
game content. SQLite is used only by the Windows/Python toolchain. The Amiga
receives small scenario-specific binary files and has no database dependency.

## Delivered data model

- 64 researched NATO and Warsaw Pact unit types imported from the editable
  `data\units\unit_types.csv` seed.
- Lookup tables for factions, nations, echelons, categories, mobility classes,
  and formation kinds.
- Self-referencing formation records that support regiments, battalions,
  squadrons, companies, company teams, platoons, and detachments.
- Scenario units that reference both a unit type and a formation.
- Separate scenario state for strength, morale, suppression, and readiness.
- One 1985 demonstration order of battle with five formations and eleven units.
- Database integrity, foreign-key, hierarchy, coordinate, and runtime-limit
  validation.
- Deterministic CSV exports for readable Git history and spreadsheet review.

The working database is `data\database\battfulda.sqlite`. Its reproducible
definition is split between `schema.sql`, `seed.sql`, `map_seed.sql`,
`scenario_seed.sql`, the unit-type seed CSV, and the production map-cell CSV.
Schema version 2 adds the A3.1 map tables while preserving this relational
unit-data foundation.

## Command-line workflow

Validate the current database:

```powershell
cd C:\Repositories\Games\BattFulda
python .\tools\manage_database.py validate
```

Export readable snapshots:

```powershell
cd C:\Repositories\Games\BattFulda
python .\tools\manage_database.py export
```

Compile the A2.1 data files:

```powershell
cd C:\Repositories\Games\BattFulda
python .\tools\manage_database.py compile
```

Create the database from its reproducible sources on a new checkout:

```powershell
cd C:\Repositories\Games\BattFulda
python .\tools\manage_database.py init
```

`init` refuses to overwrite an existing database. The explicit `--force`
option is reserved for deliberately rebuilding it from the seed sources.

## Compiled formats

All multibyte integers are big-endian to match the 68020's native byte order.

### `unit_types.bin`

- Magic: `BFUT`
- Version, count, record size, and string-table offset
- Fourteen-byte records containing faction, nation, echelon, category,
  mobility, seven ratings, and a display-name offset
- Null-terminated ASCII display-name table

### `formations.bin`

- Magic: `BFFM`
- Version, count, record size, and string-table offset
- Nine-byte records containing formation ID, parent ID, faction, nation,
  formation kind, command rating, base morale, and display-name offset
- Parent ID `255` means the formation has no parent
- Null-terminated ASCII display-name table

### `a2_scenario.bin`

- Magic: `BFSC`
- Scenario and map metadata, cursor position, formation count, unit count,
  record size, and string-table offset
- Version 2 uses eleven-byte unit records containing unit ID, type ID,
  formation ID, position, strength, morale, suppression, readiness, and a
  display-name offset
- Null-terminated ASCII scenario-unit display-name table

Version 1 was the A2.1 foundation format. Version 2 adds scenario-unit names
for the A2.2 runtime; incompatible versions are rejected rather than guessed.

## Acceptance

```powershell
cd C:\Repositories\Games\BattFulda
.\build-amiga.ps1 -Clean -Test
```

Acceptance requires all database and legacy data tests to pass, a successful
A1200 build, and an ADF containing `unit_types.bin`, `formations.bin`, and
`a2_scenario.bin` alongside the A1 files.
